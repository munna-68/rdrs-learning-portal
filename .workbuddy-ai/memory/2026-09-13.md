# 2026-09-13

## Built: RDRS Learning Portal (initial build)

Built the complete app from the supplied spec — Vite + React + Tailwind, no backend,
localStorage as the only persistence. 11 video modules, YouTube IFrame API watch-time
tracking, 80% unlock threshold, client-side PDF certificate.

Key decisions:
- Watch time accumulates **wall-clock seconds while PLAYING**, not playhead position,
  so seeking forward earns nothing. 1s poll, 3s cap per tick, clamped to video duration.
- `estimatedDuration` per module is only a fallback denominator until the player reports
  the real duration; then it's discarded. Keeps the overall bar meaningful on first visit.
- Certificate is real DOM at 1123×794, kept mounted off-screen, rasterised at 2× with
  `html2canvas-pro`, placed on a landscape A4 page with `jsPDF`. Both libs are dynamic
  imports so the initial bundle stays ~55 kB gzipped.
- Tailwind pinned to **v3.4** deliberately — v4 emits `oklch()` which plain html2canvas
  can't parse.
- Unlocking is a one-way door: once `completedAt` is stamped, a later more accurate
  duration reading can't re-lock an earned certificate.

Verification: built a CDP harness driving the real production bundle in headless Chrome.
46 checks green on both dev and prod. Real YouTube playback banked ~8s of watch time in
~9s. Downloaded PDF verified at 1 page, MediaBox 841.89 × 595.28 pt.

## Added: handoff docs + content checker (for the real course videos)

munna-68 will hand this repo to a future agent along with the real YouTube links, the
module order, and a line of detail per module. Wrote the guide for that agent.

- **`AGENT_HANDOFF.md`** (376 lines) — the primary deliverable. Orients the agent, states
  the job is *content not code*, gives a field reference for `course.js`, a worked
  example, link→ID conversion table, a house style for titles/summaries with good/bad
  examples, the verification workflow, gotchas, and a done checklist. Includes a "do not
  touch" list so an agent doesn't rewrite verified logic.
- **`scripts/check-course.mjs`** — content verifier. Shape checks (unique ids, valid
  11-char video IDs, no video reused across modules, stub summaries, positive durations)
  plus network checks. Two things make it genuinely useful:
  - **oEmbed** (`youtube.com/oembed`) returns 200 only for videos that may be embedded,
    and 400/401/404 for private/deleted/embed-blocked ones. That is the #1 silent failure
    mode of a content swap — the video plays fine in a browser tab and refuses to play in
    the app with no error in the UI.
  - **`"lengthSeconds"`** scraped from the watch page gives the real duration with no API
    key, so `estimatedDuration` can be filled accurately instead of guessed.
  Flags: `--offline`, `--json`. Exits non-zero on error so it can gate a build.

**Proved the checker actually catches failures** rather than just decorating the repo:
backed up `course.js`, injected four faults (duplicate video ID, malformed ID, stub
summary, zero duration), ran it — all four caught, exit 1 — then restored from backup and
confirmed the md5 matched byte-for-byte.

## Fixed: hardcoded 80% in UI copy

While checking how much was hardcoded before documenting it, found the module count is
fully derived (nothing hardcodes 11), but the **threshold was hardcoded as prose in three
places** — Dashboard "Watch 80%…", the "X% to go" arithmetic, and WelcomeScreen
"unlocks at 80% completion". Since the handoff doc tells a future agent the threshold
lives in `COMPLETION_THRESHOLD`, made that true: all three now interpolate the constant.
Zero behaviour change at 0.8; full regression suite re-run green.

Also worth noting: my first grep for this used `\b` word boundaries, which **BSD grep
does not support** — it silently returned "none found" and I nearly documented a false
claim. Re-ran with ripgrep and found the real answer.
